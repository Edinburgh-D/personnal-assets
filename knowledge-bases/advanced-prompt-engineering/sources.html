来源与延伸阅读

本知识库优先采用模型与平台提供方的当前技术文档，并用 OWASP 的生成式 AI 安全资料补足提示注入和权限边界。具体接口、模型名称与推荐方式会变化，使用时应回到原文核对。

官方指南 · 评估方法 · 结构化输出 · 安全边界

正文没有把某个模板描述成跨模型永远有效的公式。不同模型家族对示例、推理指令、消息角色和参数的响应并不相同，同一家平台也会随版本更新建议。因此，章节保留的是较稳定的系统原则：明确目标与权限、选择相关上下文、让中间结果可检查、用评估比较版本，并把工具与高后果动作放在提示之外约束。

  • OpenAI：Prompt engineering

    一手技术文档 · 访问于 2026-11-04

    用于核对消息角色、上下文提供、示例和生产提示版本化等基础原则。文档明确指出模型输出具有非确定性，并建议固定生产模型版本、建立测试与评估套件。

  • OpenAI：Reasoning best practices

    一手技术文档 · 访问于 2026-11-04

    用于区分推理模型与一般生成模型的提示方式。它建议对推理模型保持直接、明确，不必强迫展示逐步思维，并强调给出具体目标和约束。

  • OpenAI：Evaluation best practices

    一手技术文档 · 访问于 2026-11-04

    支撑评估闭环：先定义目标，再收集数据、确定指标、运行比较并持续评估。正文关于分类、打分与成对比较通常比无约束开放判断更易稳定测量，也来自这份指南。

  • OpenAI：Structured model outputs

    一手技术文档 · 访问于 2026-11-04

    用于说明结构化输出与普通 JSON 模式的区别。模式约束能提高字段结构的一致性，但文档也提醒，结构正确并不会自动保证字段内容在事实和业务上正确。

  • Anthropic：Prompting best practices

    一手技术文档 · 访问于 2026-11-04

    用于交叉核对清楚直接的说明、示例结构、长上下文与提示链。文档把多阶段调用定位为可检查中间输出或强制流程结构的方式，而不是对所有任务都必需的仪式。

  • Google AI for Developers：Prompt design strategies

    一手技术文档 · 访问于 2026-11-04

    提供跨平台参照，包括清晰指令、补充上下文、示例一致性、复杂任务拆分、链式与并行聚合。文档同样把提示设计描述为需要观察结果后反复实验的过程。

  • OWASP GenAI：LLM01 Prompt Injection

    权威安全社区资料 · 访问于 2026-11-04

    用于提示注入的定义、直接与间接输入风险，以及“没有万无一失文本防御”的边界。正文采用分层缓解思路：限制权限、隔离不可信内容、验证输出，并为高后果动作保留人工确认。
